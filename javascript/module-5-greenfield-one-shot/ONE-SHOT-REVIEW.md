# One-shot output review

This folder is intentionally weak. It is not a recommended solution.

Use the review checklist before revealing the reference solution:

- Which requirements are silently changed or ignored?
- Which architectural decisions were made without approval?
- Can the triage logic be tested without HTTP?
- Are error responses consistent with the acceptance criteria?
- Do tests verify behavior or merely confirm that the server starts?
- What unnecessary scope or dependencies were introduced?
- How large would the review burden be if this arrived as one pull request?
